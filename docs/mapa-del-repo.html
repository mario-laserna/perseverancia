Open MCT es un tablero de control de misión que arranca vacío, al que le enchufas plugins que dicen qué medir y de dónde sacar los datos, para que él los dibuje en gráficas que siguen todas el mismo reloj.

Clonado en ~/codigo/openmct, sin instalar dependencias ni cambiar nada Todas las rutas son relativas a esa carpeta

El mapa

Arriba, lo que pasa una sola vez al arrancar: cada plugin se apunta en las listas del núcleo. Abajo, lo que se repite con cada medida: el dato sale del proveedor, la API de telemetría lo reparte, la serie del plot lo ordena y la GPU lo pinta.

Un dato, tal como viaja

Un dato es un objeto plano de JavaScript. El generador de ejemplo crea uno así en example/generator/generatorWorker.js:173:

{ utc: 1792256400000, sin: 0.42, cos: 0.91, ... }   // utc = milisegundos; el resto, valores medidos

Open MCT no sabe qué campo va en cada eje hasta que lee los metadatos. Ahí utc lleva la pista domain (eje X) y sin lleva range (eje Y). La gráfica usa el primer range como Y (src/plugins/plot/configuration/PlotSeries.js:118) y saca el número con datum[source] (src/api/telemetry/TelemetryValueFormatter.js:118).

El pluginuna función install(openmct)

Un plugin es una función que recibe openmct y se apunta en sus listas con addType, addProvider o addRoot. openmct.install(p) solo ejecuta p(openmct). Casi todo Open MCT, gráficas incluidas, está hecho de plugins.

Los metadatostelemetry.values

Es la ficha técnica de cada medida: cómo se llama cada campo, en qué unidad viene y si va en el eje X (domain) o en el Y (range). Sin ficha, la gráfica no sabe qué dibujar. Puede ir dentro del propio objeto.

El proveedorrequest · subscribe

Es el enchufe con la fuente de datos real. Tiene dos métodos. request devuelve los datos de una ventana pasada (start–end) y subscribe llama a una función con cada dato nuevo. Si diez vistas miran lo mismo, Open MCT se suscribe al proveedor una sola vez.

El tiemporeloj y ventana

Todas las vistas comparten un reloj y una ventana visible. En modo fijo la ventana no se mueve. En tiempo real el reloj local avanza cada 100 ms y la ventana avanza con él. Por eso varias gráficas abiertas a la vez van sincronizadas.

Cómo conectamos Percy

Percy ya calcula en cada fotograma su velocidad, su rumbo y su posición. Para verlos en Open MCT hay que sacar esos números de la página del rover y escribir un plugin que haga el papel del generador de ejemplo. Es decir, las dos cajas de color óxido del mapa.

Página del rover localhost:5173/→ cada 100 ms → BroadcastChannel 'percy'→ Plugin Percy en /control.html→ API de telemetría→ gráfica

Propongo dos pestañas servidas por el mismo Vite de tu proyecto: el rover en una y Open MCT en otra. Al tener el mismo origen pueden hablar con BroadcastChannel, que viene en el navegador. Así no hace falta servidor ni WebSocket, y la separación se parece a la de una sala de control real.

paso 2El plugin Percy

Un archivo nuevo, src/percy-plugin.js. Hace cuatro cosas: crea una carpeta «Percy» en el árbol (addRoot), entrega sus tres medidas con su ficha (objects.addProvider), declara el tipo y registra el proveedor de telemetría. Cada medida lee su propio campo del mismo mensaje gracias a source.

const MEDIDAS = [
  { key: 'velocidad', nombre: 'Velocidad', unidad: 'm/s' },
  { key: 'rumbo', nombre: 'Rumbo', unidad: '°' },
  { key: 'altura', nombre: 'Altura', unidad: 'm' },
];

export default function PercyPlugin() {
  return function install(openmct) {
    const canal = new BroadcastChannel('percy');
    const historial = [];            // lo recibido desde que se abrió la pestaña
    const oyentes = new Set();
    canal.onmessage = ({ data }) => {
      historial.push(data);
      oyentes.forEach((cb) => cb(data));
    };

    openmct.types.addType('percy.medida', { name: 'Medida de Percy', cssClass: 'icon-telemetry' });
    openmct.objects.addRoot({ namespace: 'percy', key: 'rover' });
    openmct.objects.addProvider('percy', {
      get(id) {
        if (id.key === 'rover') {
          return Promise.resolve({
            identifier: id, name: 'Percy', type: 'folder',
            composition: MEDIDAS.map((m) => ({ namespace: 'percy', key: m.key })),
          });
        }
        const m = MEDIDAS.find((m) => m.key === id.key);
        return Promise.resolve({
          identifier: id, name: m.nombre, type: 'percy.medida',
          telemetry: { values: [
            { key: 'utc', name: 'Hora', format: 'utc', hints: { domain: 1 } },
            { key: 'value', source: m.key, name: m.nombre, unit: m.unidad, hints: { range: 1 } },
          ] },
        });
      },
    });

    openmct.telemetry.addProvider({
      supportsSubscribe: (obj) => obj.type === 'percy.medida',
      subscribe(obj, callback) {
        oyentes.add(callback);
        return () => oyentes.delete(callback);
      },
      supportsRequest: (obj) => obj.type === 'percy.medida',
      request: (obj, { start, end }) =>
        Promise.resolve(historial.filter((p) => p.utc >= start && p.utc <= end)),
    });
  };
}
